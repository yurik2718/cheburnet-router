# engine/invariants — что должно быть истинно на настроенном роутере

Один список инвариантов data-plane и **четыре потребителя** одного списка:

| Потребитель | Как использует |
|---|---|
| диагностика (`install/diagnostics.uc`) | печатает чек-лист ПЕРВОЙ секцией — разбор жалобы начинается с «что не на месте», а не с сырых дампов |
| QEMU-тесты | утверждают ровно эти инварианты вместо самодельных `grep` в каждом тесте |
| watchdog *(следующий шаг)* | зовёт `check.uc --repairs` и чинит починимое |
| панель *(позже)* | «всё на месте» вместо трёх разрозненных лампочек |

**Зачем именно так.** Знание «что должно быть на месте» было размазано по тестам, шагам и голове
мейнтейнера — поэтому оба инцидента (маршрут без фолбэка, DNS без резервного пути) прожили при
полностью зелёных тестах: каждый кусок по отдельности был правильным. Новый инвариант теперь
добавляется в ОДНОМ месте.

## Раскладка (как в `preflight/`)

- **`invariants.uc`** — ЧИСТАЯ оценка: сырой вывод команд + контекст → отчёт. Разбор текста тоже
  здесь, поэтому он под юнитами (`tests/`).
- **`gather.uc`** — импурный сбор (`ip`/`nft`/`ps`/`uci`). Имена цепочек, номер таблицы, метка,
  пользователь резервного DNS — из модулей-владельцев, не хардкод.
- **`check.uc`** — CLI. `exit 0` = отклонений нет, `1` = есть.

```sh
ucode -R gather.uc | ucode -R check.uc             # человеку
ucode -R gather.uc | ucode -R check.uc --json      # панель/тесты
ucode -R gather.uc | ucode -R check.uc --repairs   # чем чинить (вход watchdog'а)
```

## Инварианты

| id | severity | смысл | чинится |
|---|---|---|---|
| `wan_default` | critical | у роутера есть путь наружу помимо туннеля | `ifup wan` |
| `tunnel_route` | critical | трафик уходит в туннель (обе half-route) | `--arm` |
| `killswitch` | critical | цепочка загружена **и не пустая** | firewall-шаг |
| `direct_rule` | critical | правило направления direct-трафика есть | `reapply` |
| `direct_table` | critical | таблица ведёт в **текущий** WAN (ловит протухший) | `reapply` |
| `mark_chain` | important | адреса из direct-списка помечаются | firewall-шаг |
| `dns_rule` | important | резервный путь DNS включён | `reapply` |
| `dns_fallback` | important | резервный экземпляр DoH жив и с **нашим** резолвером | doh-шаг |
| `dns_main` | important | основной экземпляр DoH жив (резолв идёт туннелем) | **не чинится сам** |
| `dns_owners` | important | у экземпляров разные владельцы (иначе резервный путь фиктивен) | doh-шаг |

В режиме «в поездке» вместо четырёх правил направления проверяется один `travel_closed`: мимо
туннеля не уходит ничего, включая резервный DNS (fail-closed, см. [[encrypted-dns]]).
В аварийном режиме (`paused`) проверок нет вовсе — защита снята осознанно; отчёт говорит об этом
прямо, а сторож не вмешивается.

> [!important] Почему `dns_main` без автопочинки
> При мёртвом туннеле основной экземпляр DoH обречён: его bootstrap-запросы уходят в туннель и
> молчат, а на молчащих серверах демон уходит в crash-loop (баг апстрима, конфигурацией не
> лечится — [[encrypted-dns]]). Требовать «оба живы» значило бы держать чек-лист красным по
> причине, которую мы устранить не можем, и гонять сторожа вхолостую. Инвариант остаётся —
> человек видит, что резолв идёт мимо туннеля, — но чинить его автоматически нечем.

`severity`: **critical** — дом без интернета или утечка; **important** — деградация, которую
человек заметит не сразу.

## Как добавлять инвариант

1. Проверка в `evaluate()` — с `title` человеческим языком, `detail` (что видим сейчас) и `fix`
   (команда). 2. Факт в `gather.uc`, если нужен новый. 3. Юнит на ОБА исхода в `tests/`.
Не добавляйте инвариант, поломку которого никто не видел: защита от призрака стоит поддержки
(CLAUDE.md, принцип 4).

Тесты: `make test-engine`. На живой системе — `make qemu-dns-fallback` (проверка 9).
