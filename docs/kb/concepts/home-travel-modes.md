# Режимы HOME и TRAVEL

> [!tip] TL;DR
> **HOME** — split: домены из direct-списка напрямую, остальное в туннель. **TRAVEL** —
> full tunnel: вообще всё через VPN. Переключение — из панели ([[web-wizard]]), ubus-метод `set_mode`.

## Зачем два режима

| Режим | Когда | Поведение |
|---|---|---|
| **HOME** | основной режим | [[dnsmasq-nftset\|direct]]-домены → напрямую; остальное → [[amneziawg\|туннель]] |
| **TRAVEL** | нужен полный туннель | **весь** трафик → туннель, исключений нет |

В TRAVEL прямой путь не нужен — полный туннель проще и безопаснее.

## Как реализовано

Переключение — это **добавить/убрать набор правил направления** (`ip rule` + пометка `direct`
в таблицу 100), а не перестроить систему. Дёшево и предсказуемо. Механика — в [[policy-routing]].
При этом [[kill-switch]] в TRAVEL автоматически строже (нет легальных исключений для WAN).

## Где хранится состояние

Текущий режим — это состояние в конфиге (UCI), persistent через перезагрузку и sysupgrade.
Отдельного «магического» файла нет — режим выводится из наличия правил/настройки.

> [!important] Только web-UI и CLI
> Аппаратные кнопки/слайдеры не поддерживаем: поведение fragile (debounce, зависит от модели),
> у большинства роутеров их нет, а целевой пользователь ходит через
> `http://192.168.1.1/cheburnet/`. (Инвариант из v1.)

## Из консоли

```bash
ubus call cheburnet set_mode '{"mode":"travel"}'   # или "home"; нужна admin-сессия ubus
ubus call cheburnet status                          # текущий режим + состояние туннеля
```

Переключение переприменяет firewall (`install/reapply.uc`: kill-switch строже, правил направления
нет) и DNS-шаг (в travel nftset пуст). `install.json` отражает применённое состояние: не удалось —
прежний режим возвращается.
